# 多 Agent 协作守则

> 原则：**通过显式状态协调，不从对话推断所有权。** 本技能定义行为，不定义 CLI 语法。

## 标准工作循环

1. 读 workspace 状态、相关消息与任务详情（描述、依赖、revision、租约）；
2. 同步相关受管文档后再编辑；
3. `astral todo claim <id>` 认领恰好一个你打算动手的任务；
4. **确认认领成功后才做实质工作**；
5. Presence 设为真实状态并关联当前任务；
6. 在被授予的 scope 内工作；
7. 长任务期间续租约、读新消息/事件；
8. 发布结果前再同步一次，显式解决文档冲突；
9. 以 `done` / `blocked`（附摘要）收尾；
10. 释放不再持有的所有权，Presence 归位。

认领失败时不得继续做实质重复工作，除非人明确要求并行探索。

## Presence 状态（如实填写）

`idle`（可用）· `planning`（读/拆解）· `working`（产出中）· `waiting`（等已知外部依赖）·
`blocked`（需干预才能继续）· `reviewing`（评审他人产出）。

状态注释写「现在正在发生什么」，不写乐观的完成预告。

## 所有权与租约

- **Presence 不是所有权；有效的 Task 租约才是。**
- 租约临近过期且仍在工作就续租；无法继续就释放或按策略标 blocked。
- 不偷、不强制释放他人的任务；接管必须有人类明确授权。
- 租约保护的是协调，不是数据访问——workspace scope 照样要遵守。
- 不认领超过自己能同时推进的任务数，除非 workspace 策略允许批量。

## 消息

只在**会改变对方下一步行动**时发消息：请求评审、报告阻塞、宣布依赖就绪、交接、
冲突警告、回应定向请求。Presence 已表达的信息不要重复成聊天。

好消息的结构：`上下文 → 变更/结果 → 请求的下一步`。

## 阻塞

1. 任务/Presence 标 blocked；2. 写清**确切的**缺失依赖或决策；3. 私信责任方（若已知）；
4. 不发明超出 scope 的绕行方案；5. 是否释放任务给他人接手按 workspace 策略。
报告阻塞就如实是阻塞——不要让任务无限期停在 working。

## 交接摘要应包含

改了什么 · 任务当前状态 · 相关文档路径 / commit / PR 引用 · 跑过哪些检查及结果 ·
未解决的风险或冲突 · 具体下一步。不包含私有思维链，给证据与决策即可。

## 文档冲突

保留 base/local/remote 三方 → 先看双方意图 → 意图清晰才合并，否则请求评审或标 blocked；
**绝不因本地更新就无条件覆盖**（详见 documents-sync.md）。

## 秘密与权限

秘密（token、密钥、密码）永不进：消息、任务描述/评论、Markdown 文档、调试日志、
提交信息。需要的能力超出当前 scope 时，申请最小附加授权，不要索要宽泛人类凭证。

## 人工干预

人的暂停 / 撤销 / 强制释放 / 改派 / 策略变更**优先于一切 Agent 协调**。失去授权时：
停止受保护写入、不对授权失败循环重试、安全保存未同步的本地工作、报告状态与未同步内容。

## 并行

任务相互独立或明确设计为并行探索时才并行；不为并行而并行——多个 Agent 无协调理由地
编辑同一文档就是制造冲突。

## 完成标准（Definition of Done）

请求的产物存在 · 相关校验/测试已跑（在可能范围内）· 共享状态已同步或冲突已显式记录 ·
结果摘要足以让下一位（人或 Agent）无需重构隐藏推理即理解 outcome · 不再需要持有租约。
